# Frantic #33 delivery report — Sourcey docs for Wakapi

**Deliverable:** a live Sourcey-generated API reference for [Wakapi](https://github.com/muety/wakapi) (MIT, 4,473 stars, last push 2026-11-08), built from the OpenAPI spec shipped in the repo at pinned commit [`c561bbc174d139d2d3f8ee222ca61671cdc3caf1`](https://github.com/muety/wakapi/commit/c561bbc174d139d2d3f8ee222ca61671cdc3caf1).

- **Public URL:** https://merioneeason.github.io/wakapi-api-docs/ — open it first. The API Reference tab lists all 22 operations (summaries, heartbeats, projects, statistics, leaders, badges, diagnostics, health); the Guide tab has a getting-started page, an authentication page, and a worked heartbeat `curl` example.
- **What changed:** Wakapi's API was documented only as a raw Swagger file inside the repo (`static/docs/swagger.yaml`) — `wakapi.dev/api` returns 404 and there is no public, linkable API reference. This site turns that shipped spec into a navigable reference with search, per-operation pages, and `llms.txt` agent context, plus a short guide written from the spec itself.
- **How it was built (reproducible):** `npx sourcey --version` → `3.9.5`; `sourcey build -c ./sourcey.config.ts` (config in this repo under `site-src/`, `baseUrl: "/wakapi-api-docs/"`, tabs Guide + API Reference). Build output: "22 operations and 817 field rows. Pages: 5." The same build was re-run under runx governance: `runx skill ./skill --run-id wakapi-sourcey-docs-1` → status `sealed`, outcome `completed`, receipt `runx:receipt:sha256:4dd035ca05cbb0e35ed42dfb2f244390e79990e1d2a9a9e31f472469bfc0fff5`; `runx verify` on that id returned `valid: true` (2 receipts, no findings). `runx --version` output is exactly `runx-cli 0.11.1`.
- **Coverage check:** 22/22 operations from the spec appear in `api.html` (spot-checked by summary text: "Retrieve a summary", "Push a new heartbeat", "/heartbeat", "/compat/wakatime/v1/users"); 33 schemas, 21 paths, 6 tags. The spec file downloaded at the pinned commit is byte-identical to the file used for the build. Local HTTP check served the built site with 200s on `/` and `/api.html`.
- **Maintainer-facing gap 1 — the spec's license metadata is wrong:** `info.license` in `swagger.yaml` says GPL-3.0, but the repository LICENSE is MIT (confirmed in the LICENSE file and the GitHub API). Anyone generating clients or docs from the spec inherits the wrong license. Fix: change `info.license.name` to MIT in the spec.
- **Maintainer-facing gap 2 — the spec has no host:** no `host`, `basePath`, or `schemes` anywhere, so a consumer cannot tell from the spec alone where the API lives. Fix: add `host: wakapi.dev` (or the instance host) and the `/api` base path.
- **Maintainer-facing gap 3 — almost no examples:** only 2 example values in the entire spec, across 22 operations. The most-used call, `POST /heartbeat`, ships with no request example at all. Fix: add `example`/`examples` to the heartbeat, summary, and leaders operations first.
- **Maintainer-facing gap 4 — five overlapping heartbeat routes:** `POST /heartbeat`, `/heartbeats`, `/users/{user}/heartbeats`, `/v1/users/{user}/heartbeats`, and `/compat/wakatime/v1/users/{user}/heartbeats` (plus bulk variants), with numbered operationIds (`post-heartbeat-2` … `post-heartbeat-8`) and no guidance on which route new integrations should use. The guide on this site recommends the native endpoints and the compat endpoints only for existing WakaTime clients, but the spec itself should say that. Fix: mark the compat routes as legacy/WakaTime-only in their descriptions and give the heartbeat operations semantic operationIds.
- **Maintainer-facing gap 5 — tags without descriptions:** the six tags (badges, diagnostics, heartbeat, misc, summary, wakatime) carry no descriptions, so the reference groups endpoints without explaining the groups. Fix: add one-line tag descriptions.
- **Hosting limitation, stated plainly:** this site is published on a personal GitHub Pages project site (`merioneeason.github.io/wakapi-api-docs/`), not on a project/maintainer domain — maintainer adoption was not achievable inside the 3-hour delivery fuse. The repository contains the complete Sourcey project (`site-src/` with config, pinned spec, and guides) plus a README with the exact build command, so the Wakapi maintainer can adopt it and host the identical site on `wakapi.dev` with no further work. The maintainer merges external PRs quickly (15 external human PRs merged in the last 20 closed), so adoption is a realistic next step.
- **What to inspect first:** open the public URL, check the API Reference tab shows 22 operations, open one heartbeat operation and confirm its parameters render, then open `evidence.json` at the site root for the machine-readable packet (repo URL, commit, license, adapter, command, page list, receipt id).
